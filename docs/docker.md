# Docker（NAS で動かす）

WebToolbox を UGREEN NAS の Docker で動かし、家の中の LAN のブラウザから `http://192.168.0.100:8000/` で開けるようにする。

`server.py`（Python の標準ライブラリだけで書いた小さなサーバー）が、画面のファイル（`index.html`・`css/`・`js/`）を配り、メモ帳・付箋などの中身を NAS に保存する。

## どこに保存されるか

| もの | 保存先 | 端末どうしで |
| --- | --- | --- |
| メモ帳・メモ帳（ワイド）・付箋の中身 | NAS（`app-data/webtoolbox/docs/`） | **共有する**（家で書いたものが会社でも見える） |
| ボードの配置（どのツールをどこに置いたか） | ブラウザ（localStorage） | 端末ごと |
| タイマー・ストップウォッチ・ListTimer の状態 | ブラウザ | 端末ごと |
| UI スケール・通知のオン・オフ | ブラウザ | 端末ごと |

- メモ帳・付箋は 1 つずつしか置けず、閉じても中身は NAS に残る。もう一度置くと前の中身が出てくる
- 両方の端末で開いているときは、4 秒ごとに相手の変更を取り込む。同じものを両方で同時に書き換えたら、**あとから保存したほうが残る**
- 上書きで消えた中身は、`app-data/webtoolbox/backup/<種類>/` に 1 時間に 1 回まで控えが残る（種類ごとに 72 個まで）
- NAS に接続できないあいだは、変更をブラウザに保存しておき、上のバーに「⚠ 保存できていません」と出す。つながったら自動で保存する

## ファイル

| ファイル | 内容 |
| --- | --- |
| `server.py` | 画面のファイルを配り、中身を保存する（API は下の「API」）。配るのは `index.html`・`css/`・`js/` だけ |
| `Dockerfile` | Python 3.12（標準ライブラリだけなので `pip install` はない）。`server.py` を `0.0.0.0:8000` で動かし、中身は `/data` に保存する |
| `docker-compose.yaml` | 読み取り専用のコンテナ・権限を全部外す・プロセス数とメモリの上限などの安全設定。つなぐのは `/data` だけ |
| `.env.example` | 動かすユーザーとつなぐ場所の見本。`.env` にコピーして使う（git に入れない） |
| `.dockerignore` | 許可リスト方式。イメージに入れるのは `server.py`・`index.html`・`css/`・`js/` だけ |

| コンテナの中 | つなぐ先（`.env`） | 扱い |
| --- | --- | --- |
| `/data` | `WT_DATA_DIR`（`/volume1/app-data/webtoolbox`） | 書き込み（中身 `docs/` と控え `backup/`） |

- WebToolbox は `WT_BIND_IP:WT_PORT`（NAS の LAN の IP アドレスとポート）だけで待ち受ける。ポートはほかのコンテナと重ならない番号にする
- 受け付けるホスト名は `WT_ALLOWED_HOSTS`（DNS リバインディング対策）。書き込みは、このページ自身からだけ受け付ける
- コンテナは、このアプリ専用の NAS ユーザー `svc-webtoolbox`（`WT_UID`）・グループ `users`（`WT_GID`）で動き、ファイルを**グループのメンバーも書き換えられる設定**で作る（`WT_UMASK=0002`）
- 画面のファイルには CSP（読み込むのは自分のファイルだけ・ほかのサイトに埋め込ませない）を付ける。`Cache-Control: no-cache` なので、更新したらリロードだけで反映される

## NAS の共有フォルダのアクセス権（UGREEN の ACL）

- UGREEN の共有フォルダには、ふだん見える権限（`ls` の `drwxrwxrwx`）とは別に **UGREEN 独自のアクセス権**が付いていて、こちらが優先される
- そのため、**UGOS に登録されていない UID（Dockerfile の既定の 10001 など）は、共有フォルダを読み書きできない**。コンテナは UGOS で作ったユーザーで動かす
- アプリごとにユーザーを分ける（共通のユーザーにすると、どのアプリのコンテナからも、ほかのアプリのデータが読めてしまう）
- **`dev` など、リポジトリのある共有には許可しない**（ほかのリポジトリの `.env` などが読めてしまうため）

## はじめて動かす手順

### 1. アプリ専用の NAS ユーザーを作る

UGOS の **コントロールパネル → ユーザー** で、ユーザーを作成する。

| 項目 | 値 |
| --- | --- |
| ユーザー名 | `svc-webtoolbox` |
| パスワード | 長いランダムな文字列（このユーザーでログインすることはないので、控えなくてよい） |
| グループ | `users`（既定のまま） |
| 共有フォルダの権限 | `app-data`: **読み書き**、**ほかはすべて「アクセス不可」** |
| アプリの権限（SMB・Web など） | すべてオフ（コンテナを動かすためだけのユーザー） |

作ったら SSH で番号を調べる。`uid=` が `WT_UID`、`gid=` が `WT_GID`（`users` なら多くは 100）になる。

```bash
ssh <管理者のユーザー名>@192.168.0.100
id svc-webtoolbox
```

### 2. フォルダを用意する

エクスプローラー（Mac なら Finder）で `app-data` の中に `webtoolbox` フォルダを作る（空でよい）。

- 共有フォルダの権限は、フォルダを作ったときに、そのときの共有フォルダの権限が写される。**手順 1 より前に作ったフォルダには、`svc-webtoolbox` の権限が付かない**。その場合は消して作り直す

### 3. `.env` を作る

リポジトリのフォルダ（例: `/volume1/docker/WebToolbox`）に `.env` を作る。

```bash
cd /volume1/docker/WebToolbox
cp .env.example .env
vi .env
```

`WT_UID`・`WT_GID` を手順 1 で調べた番号にし、場所（`/volume1`）・IP アドレス・ポート・ホスト名を合わせる。`WT_ALLOWED_HOSTS` には、ブラウザのアドレス欄に入れるもの（IP アドレスや NAS の名前）をすべて書く。

### 4. 起動する

```bash
cd /volume1/docker/WebToolbox
sudo docker compose up -d --build
sudo docker compose ps
sudo docker compose logs
```

`STATUS` が `Up … (healthy)` になり（起動から 30 秒ほどかかる）、ログに「WebToolbox を起動しました」と出れば成功。ブラウザで `http://192.168.0.100:8000/` を開く。

開けないとき:
- 「このアドレスでは開けません」と出る → `.env` の `WT_ALLOWED_HOSTS` にそのアドレスを足して、`sudo docker compose up -d` で作り直す
- 「次の場所を読み書きする権限がありません」とログに出る → 手順 1 の共有フォルダの権限・手順 2 のフォルダ・`WT_UID` を確かめる
- つながらない → UGOS のファイアウォールを使っていれば、LAN からそのポートへの接続を許可する

### 前の版（nginx だけの版、0.1.0）から更新するとき

手順 1〜3 を行い、`.env` に `WT_UID`・`WT_GID`・`WT_DATA_DIR`・`WT_ALLOWED_HOSTS` を足してから、手順 4 を行う。

ブラウザに残っていたメモ帳・付箋は、新しい版をはじめて開いたときに NAS へ移る。

- 同じ種類のメモ帳を何個も置いていたら、区切り線（`――――――――`）を入れて 1 つにまとめる
- 付箋は、付箋ボードの中の 1 枚ずつになる（空の付箋は移さない）
- 2 台目のブラウザで開いたときは、NAS にある中身の後ろに足す（同じ文章はもう一度足さない）
- 移すのは NAS の中身を読めてから（つながらないあいだは、ブラウザに取っておいて、つながったときに移す）

## ふだんの操作

すべて SSH で、リポジトリのフォルダで実行する。

| したいこと | コマンド |
| --- | --- |
| ログを見る | `sudo docker compose logs -f`（Ctrl+C で抜ける） |
| 再起動する | `sudo docker compose restart` |
| 止める | `sudo docker compose down` |
| プログラムを更新する | リポジトリを更新してから `sudo docker compose up -d --build` |

- 画面のファイルはイメージの中にコピーしているので、**リポジトリを書き換えただけでは反映されない**。`--build` で作り直す
- 更新したら、`docker-compose.yaml` の `image:` のタグ（`webtoolbox:0.2.0`）も上げる

### 上書きしてしまった中身を戻す

1. `app-data/webtoolbox/backup/<種類>/` から戻したい時刻の控えを選ぶ（種類は `memo`・`memo2`・`stickies`）
2. `sudo docker compose stop` で止める
3. その控えを `app-data/webtoolbox/docs/<種類>.json` に上書きコピーする
4. 控えの `rev` を、`docs/` の中のどのファイルの `rev` よりも大きい番号に書き換える（小さいままだと、開いているブラウザが取り込まない）
5. `sudo docker compose start` で動かし、ブラウザをリロードする

### 中身を全部消したいとき

各ツールの中で消す（メモ帳の文字を消す、付箋を削除する）。`docs/` を消すだけだと、開いたことのあるブラウザが手元に残っている中身を送り直す（NAS の中身が消えても失われないようにするため）。

## API

| | |
| --- | --- |
| `GET /api/docs?after=<rev>` | `rev` が `after` より新しい中身だけを返す。`{"rev": 最新の rev, "docs": {"memo": {"rev": 3, "data": {...}}}}` |
| `PUT /api/docs/<種類>` | `{"data": ...}` を保存して `{"rev": 新しい rev}` を返す。`Content-Type: application/json` だけ。1 つ 1MB まで。種類は 32 個まで（超えると 507） |
| `GET /healthz` | 死活確認（ホスト名を問わず `ok`） |

`rev` は全体で増え続ける番号。種類の名前は英小文字・数字・`-`・`_`（32 文字まで）。

## 気をつけること

### ボードの配置はブラウザごと・アドレスごと

配置やタイマーなどは「ブラウザ × アドレス（`http://192.168.0.100:8000` など）」ごとに分かれる。`192.168.0.100` で開いたときと `nas.local` で開いたときは別の配置になるので、**開くアドレスは 1 つに決める**（メモ帳・付箋の中身はどちらで開いても同じ）。

### デスクトップ通知は HTTP では使えない

ブラウザは、デスクトップ通知を「安全なページ」（HTTPS か `localhost`）でしか許可しない。`http://192.168.0.100:8000/` は安全なページではないので、**設定の「デスクトップ通知」はオンにできない**。終了音と画面の点滅は使える。HTTPS にするときに使えるようになる。

### ログインはない

家の LAN の中からなら、誰でも開いて中身を読み書きできる。外（会社など）から開けるようにするときは、HTTPS と一緒に入口での本人確認（Cloudflare Access や Tailscale など）を入れる。
